# 0021 — Continuous host orchestration with visible delivery state

Status: accepted · 2026-10-15

## Context

The owner clarified that the skills should turn an existing coding harness
into a complete software factory without requiring a prompt at every step.

## Drivers

- Carry an approved outcome through planning, implementation, verification,
  delivery, authorized observation, bug fixes and the next priority.
- Show milestone progress, agent contributions, proof and pending decisions.

## Options

- Separate commands for each phase, requiring repeated human coordination.
- A host-owned delivery loop composed from the existing skills and records.

## Outcome

The host agent continuously orchestrates within scoped approval, using native
workers and the existing dependency frontier. Progress updates are reports;
material scope, risk, authority and required acceptance remain human decisions.
Monitoring is configured with the owner before its access or effects are used.

## Consequences

- Board records and receipts remain authoritative; the dashboard is derived.
- Record requested and observed models separately; unknown stays unknown.
- A local snapshot or claim does not prove a worker is running.
- No scheduler, model client or second status service is added to the pack.

## Confirmation

- Owner clarification and the canonical orchestration and handoff references.
- Dashboard fixture checks and independent bounded skill-use exercises.
