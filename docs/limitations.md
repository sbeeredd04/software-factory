# Current limits


## The active host owns execution

Software Factory is eleven skills, eleven role prompts and standard-library
helpers. The coding host supplies tools, workers, model access, trust and actual
permissions. The pack adds no hosted runtime, model gateway, credential service,
background daemon or automatic schedule. Staffing follows capability and risk;
requested and observed effective models are different facts.

Role prose, local claims and hook pointers do not independently sandbox an agent.
Static generated formats and local hook fixtures do not establish native/custom
agent loading, combined Cursor/Codex compatibility or marketplace acceptance.
Raw portable skills and full project/native installation have different assets
and trust/invocation policies. See [installation](installation.md).

## Platform and network boundaries

Local filesystem helpers require Python3.11+ and POSIX descriptor/no-follow and
locking APIs. [Release-source CI](https://github.com/sbeeredd04/software-factory/actions/runs/38857687865)
passed on Ubuntu and macOS across Python3.11–3.13 at published commit
`bc206b3751da7c3ca0cc32436893be96bfe6c42b`; local execution also includes
macOS/Python3.12. These checks do not establish native Windows or WSL execution,
live coding-host loading/trust or real provider access. Portability and workflow
configuration alone do not establish those capabilities.

Kernel/admin observation is local; explicit bootstrap acquisition and consented
BMad provisioning have network/subprocess boundaries. Doctor can invoke available
`gh auth status` and verified local hook fixtures. Read-only project diagnostics
are not automatically no-provider/offline diagnostics. Developer tooling can use
pinned download caches; it adds no shipped third-party Python dependency.

## Provenance is not authority or effect

Hashes bind bytes; labels/names do not authenticate people. A configured recipe,
connector or enabled flag is not permission, capability, account access or a
successful effect. A Git SHA, graph link or local done label alone is not proof
that a revision shipped. Keep unknowns and failed/stale receipts visible.

Operations need actual capability, scoped access, source/data policy and a finite
window. Observation ends with the active session unless a supported host schedule
is separately authorized and observed. Read access does not grant repair, rollback,
deploy or messaging authority. Empty or incomplete results are not healthy proof.

## Completion and publication

An implementation, a green fixture and an evidence-accepted epic are separate.
Applicable reserved checkpoints block their dependents; independent authorized
work can continue. Epic acceptance may be evidence-bound delegation or a real
human decision, according to the active scope. The precise local staging
equivalent and publication require their own concrete decisions. Release, public source access,
remote maintainer integration, Pages and social posting are separately observed
and authorized outcomes. An unpublished draft or manual workflow is not a release.
