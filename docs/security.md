# Security and authority

The local kernel and administrative helpers are Python >=3.11 standard-library code. They validate and record bounded facts; they do not call a model or schedule work. POSIX descriptor/no-follow and locking APIs are required by the filesystem helpers. The bootstrap can download a release and the separately consented BMad installer can acquire its official package; [installation](installation.md) distinguishes those boundaries. Doctor can invoke available `gh auth status`, Git and verified local hook fixtures, so use the [controlled smoke fixture](smoke-test.md) when provider-free observations matter.

Prompts, hooks, local locks and hashes provide guidance or structural checks, not authentication or a permission sandbox. The host must reconcile the actual scope and permissions before commands, external access, messages or production writes. Unknown external outcomes require provider-state inspection before retry. No secret belongs in prompts, logs, fixtures or tracked receipts. The [authority contract](../skills/software-factory/references/authority.md) explains GO reuse and escalation; [SECURITY.md](../SECURITY.md) explains private vulnerability reporting.

Installer ownership guards preserve existing bytes or refuse collisions. An explicit reviewed `--allow-overwrite PATH` creates a backup for that one path; it cannot bypass a changed overlay. Uninstall preserves edited and unknown files. A refusal is a recovery boundary: inspect current bytes, ownership manifest and backups before deciding the next action. The pack adds no telemetry, auto-update, sudo or permission bypass.
