# Host invocation and trust

Choose one project host: Claude Code, Cursor or Codex. The [project installer](installation.md) generates host-specific assets from the same eleven canonical skills and eleven role prompts. Never hand-edit a generated projection; change the canonical source and reinstall after reviewing the plan.

| Host | Project invocation | Installed skill path | Role treatment |
| --- | --- | --- | --- |
| Claude Code | `/software-factory` | `.claude/skills` | Project agents and policies generated by the installer. A native plugin may namespace the command. |
| Cursor | `/software-factory` | `.agents/skills` | Project role projections and Cursor policy files generated by the installer. |
| Codex | `$software-factory` | `.agents/skills` | Project custom-agent TOMLs generated by the installer; native bundle role prompts remain manual/reference assets. |

The exact [host contract](../skills/software-factory/references/hosts.md) and [distribution routes](distribution.md) cover namespacing, project versus native bundles, hooks and path details. Source `plugin.json` is a portable skills-only entry. A generated marketplace is an artifact, not an enabled installation. Stacking plugin and project hooks for the same host is outside the tested mode.

The active host owns execution, actual model availability, isolation and permission grants. Role prose cannot enforce a sandbox. Requested routing and observed effective model are separate evidence. Static projection checks and disposable hook fixtures do not prove live loading, host capacity, account access or combined Cursor/Codex shared-frontmatter tolerance. Codex hooks require explicit trust. Missing optional agent backends leave the native host worker available within its real scope; a denial never authorizes a different backend. See [team](team.md) and [agents](agents.md).
