# AGENTS.md

Guidance for coding agents and humans working **on this repository** (the Software Factory pack
itself). To *use* the factory in your own project, install the pack and talk to the
`software-factory` skill instead.

## What this repository is

Software Factory is an MIT-licensed skill pack - Markdown plus standard-library Python - that
turns a coding agent (Claude Code, Cursor, or Codex) into an autonomous software factory: one
orchestrator owns the loop from grounded intent to planned work, evidence-gated merge, deploy
proof, and a human checkpoint per epic. "BMad plans, the factory ships." BMad Method v6 is
installed separately through its own pinned installer; this repository never vendors it.

## Repository map

| Path | What lives there |
| --- | --- |
| `skills/` | The eight canonical skills. The only hand-edited skill source. |
| `agents/` | The eleven role prompts (`sf-*.md`). Canonical, never host-forked. |
| `hosts/` | Host policy files for Claude Code, Cursor, and Codex. |
| `schemas/` | JSON Schema 2020-12 documents for config, runs, and evidence. |
| `scripts/` | Validation and scanning tooling (`validate.py`, `scan_public.py`, `check_all.sh`, ...). |
| `tests/` | Standard-library `unittest` suite; fixtures in `tests/fixtures/`. |
| `templates/` | Consumer document templates (PRINCIPLES, ARCHITECTURE, CONVENTIONS, CHECKPOINT). |
| `adapters/` | Tracker adapters (BMad v6, markdown, BMad v7 stub). |
| `integrations/` | Review-bot configuration templates. Nothing is enabled by default. |
| `docs/` | Documentation, ADRs, dogfood artifacts. |
| `examples/` | Example projects and a synthetic run. |
| `dist/` | Generated release output. Never hand-edit, never commit. |
| `.github/` | Issue forms, pull request template, Dependabot, CI. |

Projections into host formats (`.claude/`, `.agents/`, `.cursor/`, `.codex/` inside a consumer
project) are generated by the installer. Never edit a generated file: fix the canonical source
and regenerate.

## Commands

Shipped code is Python >= 3.11, standard library only. No install step, no virtual environment,
no sudo. Development tools run on demand through `uvx`/`npx` and are never installed globally.

```bash
python3 -m unittest discover -s tests -v   # unit tests (SF_SKIP_NETWORK=1 skips network-marked tests)
python3 -m compileall -q install.py scripts skills tests   # syntax check
uvx ruff check .                           # lint
bash scripts/check_all.sh                  # the full static gate - run before every handoff
```

## Hard boundaries

The whole list, stated once:

1. Never run the `claude`, `cursor-agent`, or `codex` CLIs in this repository or its tests -
   not even `--version`. Validate host formats statically; tests that must prove an agent CLI
   was not invoked use PATH guard stubs.
2. Public-clean: no private names, people, absolute user paths, credentials, or private project
   content in any tracked file, generated output, or commit message. Generalize from private
   experience; never paste it. `scripts/scan_public.py` enforces this.
3. Never push directly to `main` and never force-push. Work happens on feature branches; pull
   requests target the integration branch `dev`; a maintainer merges.
4. Shipped code adds no permission bypasses, no sudo, no telemetry, no auto-updates, and no
   third-party dependencies.
5. Report verification honestly: run the commands, quote real output and exit codes. Never
   claim a check passed that was not run.

## Writing style - agent-first

Prompts give direction, focus, context, and evidence expectations. They are not rigid scripts
and not prohibition lists. Roles are tools: the eleven shipped roles are a starting team the
orchestrator staffs from as needed, not a mandatory fleet. Skills are progressive-disclosure
maps - a short `SKILL.md` (the orchestrator entry is at most 150 lines), with detail in
`references/` files linked from it. Canonical frontmatter uses only the standard keys: `name`
(matches the folder), `description` (trigger-first, at most 300 characters), `license`,
`compatibility`, and `metadata` with string values. Host-only fields are added by projections,
never in canonical files.
